# 명시 금액·무료 조건 보완 결과

## 같은 기준으로 비교

프롬프트와 평가 문장 28개는 바꾸지 않고 규칙/최종 금액 처리만 보완했어요.

| 기준 | 이전 | 보완 후 |
| --- | --- | --- |
| 문장 전체 통과 | 22/28 (78.6%) | 25/28 (89.3%) |
| 필드 통과 | 98/104 | 101/104 |
| 이전에 통과했다가 실패한 문장 | — | 0개 |

- `cost-wedding`: 축의금 15만원을 기본값 10만원으로 바꾸지 않아요.
- `cost-performance`: 티켓 9만원을 기본값으로 바꾸지 않아요.
- `cost-free`: 무료 전시에 양수 입장료를 넣지 않아요.

기존 평가에서 발견한 문제에 맞춘 보완이므로, 이 상승이 새로운 사용자 문장 전체에서도
그대로 재현된다는 뜻은 아니에요. 평가 세트 밖 표현과 부정문 등은 별도 회귀 테스트로 확인했어요.

## 앱에서 적용하는 순서

1. 문장에 적은 본인 금액이나 무료 조건
2. 조건이 없는 항목의 유사 일정 기록 평균
3. 기록도 없으면 AI 또는 규칙 기본 추정

`applyExplicitCosts`를 규칙 예측과 AI 응답 정리에 모두 적용해요.
내부 항목의 `amountSource: "user"`로 명시 금액을 구분해서 `estimateCosts`의 과거 평균이 덮지 않게 해요.
이 내부 표시는 저장되는 `EventPrediction`에는 넣지 않아요. 공용 `src/lib/types.ts`는 변경하지 않았어요.
AI 응답 정리는 모의 응답으로 테스트했으며 이 변경에서 외부 AI API를 추가 호출하지 않았어요.

## 지원 범위

- 축의금·축하금·조의금·부의금, 티켓·입장료·관람료 등 기존 항목에 대응되는 명시 금액
- `15만원`, `150,000원`, `9만 원`, `1.5만원`, `1만 5천원`, `9천5백원`, `0원`
- 무료 전시·공연·영화, 입장료 무료/0원

지원하지 않는 복잡한 문장을 본인 확정 금액으로 고정하지 않아요:

- 인당·총액·n빵: 본인 몫이라고 적지 않으면 분배하지 않아요.
- 가격 범위·과거 가격·정정·할인액·환불액·다른 사람 가격
- 서로 다른 여러 금액이나 무료와 유료가 충돌하는 문장

이 경우 기존 예측을 유지해요. 복잡한 문장 전체를 해석하는 역할은 여전히 AI가 맡아요.
무료 주차·무료 배송만으로 입장료를 0원으로 바꾸지 않아요.

## 확인

```bash
npm run test:explicit-costs
npm run test:prediction-eval
npm run eval:prediction -- --provider rules
```

채점 도구 테스트 9개, 타입 검사·린트를 통과했어요.
