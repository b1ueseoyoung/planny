# 일정 문장 이해 평가

날짜·사람·인원·누가 내는지·필수 지출 항목을 같은 기준으로 비교해요.
실제 사용자 데이터는 쓰지 않고, `cases.ts`의 합성 문장 28개를 사용해요.
앱 프롬프트의 예시(`src/lib/predict/examples.ts`)와 문장·기준일을 분리했어요.

## 실행

```bash
npm ci
npm run test:prediction-eval

# 기본 실행: 키 없이 규칙 예측 28개 평가 (외부 호출 없음)
npm run eval:prediction

# 같은 3개 문장으로 규칙과 Gemini 비교 (기본 limit: 3)
npm run eval:prediction -- --provider both

# 규칙이 놓치는 문장 3개를 선택해서 비교
npm run eval:prediction -- --provider both --ids people-without-user,payer-second-round,cost-free --limit 3

# Gemini 전체 평가: 명시적으로 28개를 지정해야 해요
npm run eval:prediction -- --provider gemini --limit 28
```

Gemini 실행 시 `.env.local`의 `GEMINI_API_KEY`와 `GEMINI_MODEL`을 읽어요.
이미 설정된 환경 변수는 파일 값보다 우선해요. 실행 중 키나 오류 본문은 출력·저장하지 않아요.
규칙 실행에서는 키 파일을 읽지 않아요.

Gemini는 앱의 `understandWithGemini`를 직접 호출해요. 앱과 같은 모델 재시도 정책을 사용하지만,
실패를 규칙 결과로 대체하지 않아서 AI가 성공한 것처럼 채점하지 않아요.
첫 호출 오류나 시간 초과가 나면 남은 Gemini 문장은 미실행으로 남겨요.
한 문장에 앱의 재시도 정책만큼 여러 API 호출이 발생할 수 있어요.
호출 사이에 1.5초 쉬지만 무료 한도를 보장하는 간격은 아니에요.

## 정답 기준

- 날짜: 고정한 '오늘'과 기본 날짜를 기준으로 정확히 비교해요. 다음 주, 월·연도 경계, 윤년, 여행 기간을 포함해요.
- 사람: 순서는 무관해요. 조사나 '친구들' 같은 그룹명, 중복된 이름은 불일치예요.
- 인원: 본인을 포함해요. 문장에서 알 수 없으면 `null`이 정답이에요.
- 결제 주체: 내가 모두 냄 / 나눠 냄 / 타인·회사가 냄 / 알 수 없음을 구분해요.
- 비용 항목: 카테고리와 의미에 맞는 항목명이 있는지 비교해요. 항공권을 단순 교통비로 대신하면 항공권 기준은 통과하지 못해요.
- 금액: 문장에 명시한 축의금 15만원, 티켓 9만원만 정확한 값으로 채점해요. 추정한 식비·항공권 가격에 임의 정답을 정하지 않아요.
- 무료·타인 부담: 양수 입장료·식비가 추가됐는지 확인해요. 0원 항목은 허용해요.
- 모호한 항목은 기대값에서 생략해요. 생략은 정답이 아니라 **채점하지 않음**이에요.

## 결과 읽기

콘솔에 문장 전체 통과 수, 응답·오류·미실행 수와 틀린 필드를 보여줘요.
`evals/prediction/results/`에 상세 JSON 보고서가 생성되며 Git에서 제외돼요.
원하는 파일은 `--out 경로.json`으로 지정할 수 있어요.

- 문장 전체 통과율: 모든 채점 항목이 맞은 문장 / 선택한 전체 문장. 오류·미실행도 분모에 포함돼요.
- 필드별 점수: 응답 완료분만 집계해요. 사람이름·날짜 등 각 필드의 `passed/total`을 함께 확인해요.
- 보고서에는 기준 문장 ID, 전체 평가 세트·프롬프트의 SHA-256, 코드 커밋과 미커밋 변경 여부, 문장별 시간과 결과를 기록해요.
- `geminiModelPolicy`는 설정한 첫 모델과 앱의 대체 정책이에요. 실제 응답 모델을 수집하지 않으므로 특정 모델의 성능으로 해석하지 마세요.
- 종료 코드 0은 평가 실행 완료를 뜻해요. 품질 오답이 없다는 뜻은 아니에요. 호출 오류는 종료 코드 1이에요.

## 범위와 한계

이 도구는 **문장 이해**를 평가해요. 과거 기록을 적용하는 `estimateCosts`, 월말 예산 계산,
가격 추정의 실제 정확도는 별도 평가가 필요해요. 합성 문장 28개는 실제 사용자 분포를 대표하지 않아요.
특히 규칙이 실패한 3개만 고른 Gemini 비교는 취약 사례 점검이며 전체 정확도가 아니에요.
필수 항목명은 허용한 표현으로 비교하므로, 의미가 같은 새 표현이 나왔을 때는 사람이 기준을 검토해 주세요.

프롬프트나 규칙을 고치기 전에 기준 보고서를 남기고, 고친 뒤 **같은 문장 ID**로 비교해요.
이 문장에만 맞추지 않도록 이후에는 새로운 검증 문장도 추가해 주세요.
